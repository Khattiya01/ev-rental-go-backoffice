# Intent: เขียน OpenAPI spec ให้ API ที่มีอยู่

## ปัญหา
ธรรมนูญโปรเจกต์ (มาตรา 6) กำหนดว่า API ต้องมี OpenAPI แต่ตอนนี้ **ไม่มี OpenAPI spec เลยสักตัว** และไม่มี
Postman collection อยู่ใน repo นี้ด้วย (มีแต่ postman collection เก่าในโฟลเดอร์แม่ EV_Rental_GO/planings/
ซึ่งอยู่นอก repo และอาจไม่ตรงกับ API ปัจจุบันแล้ว) ทำให้คนนอกทีม/AI ที่มาต่อยอดต้องอ่านโค้ด route handler
ทุกไฟล์เพื่อรู้ contract ของ API แต่ละตัว

## หลักฐาน
ยืนยันจาก `docs/planning/A1-inventory.md` — ค้นหา `openapi.json` หรือไฟล์ spec ใดๆ ใน repo ไม่พบเลย

## ผลลัพธ์ที่อยากได้
มี `docs/api/openapi.json` ที่สะท้อน API จริง อย่างน้อยสำหรับ endpoint ที่ frontend ภายนอก (เช่น mobile app
ในอนาคต หรือ IoT Gateway) อาจต้องเรียกใช้

## ใครและอะไรได้รับผลกระทบ
- ผู้ใช้กลุ่มไหน: ทีม dev เอง (ลดเวลาที่ต้องอ่านโค้ดเพื่อรู้ contract), ทีมที่จะทำ mobile/public API ในอนาคต
- ส่วนไหนของระบบ: ทุก `app/api/**/route.ts` (40 endpoint)
- ข้อมูลอะไรที่เกี่ยวข้อง: ไม่มีข้อมูลอ่อนไหวเพิ่มเติม (แค่ document contract ที่มีอยู่แล้ว)

## ข้อจำกัดที่ต้องรักษา
- ต้องสะท้อน behavior จริงของ endpoint ปัจจุบัน ไม่ใช่ design ใหม่ที่ยังไม่ได้ implement
- ไม่ควร block งาน feature อื่นเพื่อทำ spec ให้ครบ 100% ในรอบเดียว

## คำถามที่ยังไม่มีคำตอบ
- [NEEDS CLARIFICATION (scope): ทำ OpenAPI แบบ generate อัตโนมัติจาก route handler (ต้องเลือก/เพิ่ม tooling) หรือเขียนมือทีละ endpoint ตอนแตะไฟล์นั้น (ตามธรรมนูญ 9.1 — เนียนไปกับงานปกติ ไม่ต้องเปิด task ใหญ่)?]

## การตัดสิน (เจ้าของโปรเจกต์กรอก)

- [ ] **ทำ** → ไปต่อที่ `/spec` (feature ใหญ่) หรือสร้าง task ตรง ๆ (งานเล็ก)
- [ ] **ยังไม่ทำ** → ใส่ `status: deferred` พร้อมเงื่อนไขว่าเมื่อไหร่ถึงกลับมาดู
- [ ] **ไม่ทำ** → ใส่ `status: rejected` พร้อมเหตุผล **อย่าลบไฟล์** เพราะอีก 3 เดือนจะมีคนเสนอซ้ำ

**เหตุผลของการตัดสิน:**

**เส้นทางต่อไป:** `docs/specs/<F-xx>/` หรือ `docs/backlog/tasks/T-xxx.md`
