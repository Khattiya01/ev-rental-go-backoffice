# ADR-0007: `docs/backlog/tasks/*.md` ในนี้คือ source of truth ของงาน — ไม่มี external tracker

- **สถานะ:** Accepted
- **วันที่:** 2026-09-24
- **ผู้ตัดสินใจ:** ทีมพัฒนา EV Rental GO

## บริบท
ระหว่างสำรวจโปรเจกต์ (Phase A.1) ไม่พบระบบติดตามงานใดๆ ที่ใช้งานอยู่จริงในหรือรอบๆ repo นี้
(ไม่มี GitHub Issues/Projects เปิดใช้, ไม่มี Jira/Trello, ไม่มี `.github/ISSUE_TEMPLATE`)
มีเพียงไฟล์ sprint บันทึกความคืบหน้าเดิม (`SPRINT1.md`–`SPRINT5.md`, `sprint_backlog_and_detailed_plan.txt`)
อยู่ในโฟลเดอร์แม่ `EV_Rental_GO/planings/` ซึ่ง**อยู่นอก git repo นี้** (คนละ working tree)

ผู้ใช้ยืนยันว่าไฟล์ sprint เหล่านั้นเป็น**ประวัติศาสตร์งานที่ทำเสร็จหมดแล้ว** ไม่มีงานค้างที่ต้องสานต่อ

## ทางเลือกที่พิจารณา

### ทางเลือก 1: Repo เป็นหลัก (`docs/backlog/tasks/*.md` → generate `board.md`)
- ข้อดี: AI อ่านได้ตรงๆ ไม่ต้องพึ่ง API/credential ภายนอก, มี source of truth เดียวที่ผูกกับ git history
- ข้อเสีย: ถ้าทีมโตจนต้องมีคนนอกทีมเทคนิค (เช่น sales/support) เข้ามาดูสถานะงาน จะต้องมีช่องทางอื่นเสริม

### ทางเลือก 2: ใช้ tracker ภายนอก (Jira/Trello/GitHub Projects) เป็นหลัก
- ข้อดี: มี UI สำหรับคนที่ไม่ใช้ git, รายงาน/dashboard สำเร็จรูป
- ข้อเสีย: ไม่มีระบบแบบนี้ใช้งานอยู่ตอนนี้เลย — ต้องตั้งใหม่ทั้งหมดโดยไม่มีความจำเป็นเร่งด่วน

## การตัดสินใจ
**เลือก: Repo เป็นหลัก** — `docs/backlog/tasks/*.md` คือ source of truth เดียวของงาน
`docs/backlog/board.md` generate จากไฟล์ task ด้วย `node .claude/board.js` เท่านั้น **ห้ามแก้มือ ห้าม commit**
(อยู่ใน `.gitignore` แล้ว — ไม่งั้นจะ conflict ทุกครั้งที่มีหลาย PR พร้อมกัน)

เหตุผล:
- ไม่มี external tracker ใช้งานอยู่จริงเลยตอนนี้ — ใช้ default ของ kit ได้ตรงๆ โดยไม่ต้องเทียบกับของเดิม
- ไฟล์ sprint เดิมใน `planings/` เป็นประวัติศาสตร์งานที่เสร็จแล้วทั้งหมด **ไม่ import เป็น intent** (ไม่มีงานค้างให้ตัดสิน)

## ผลที่ตามมา
**ผลดี:**
- Backlog เริ่มจาก board ว่างสะอาด ไม่ต้องย้อนสร้างประวัติ 5 sprint เก่าที่ไม่มีความหมายกับงานต่อจากนี้
- งานใหม่ทั้งหมดหลัง Phase 7 เข้าทาง `/intent` → `/task` ตามปกติของ kit

**ผลเสีย / สิ่งที่ต้องยอมรับ:**
- ไม่มีการเชื่อมโยงย้อนหลังระหว่าง commit ประวัติศาสตร์ (sprint 1–5) กับ task file ใหม่ — ถ้าต้องสืบประวัติฟีเจอร์เก่าต้องไปดู git log/sprint docs เดิมเอง ไม่ใช่ผ่าน backlog ใหม่

**สิ่งที่ต้องทำเพิ่มเพราะเลือกแบบนี้:**
- ไม่มี — เริ่มต้นจาก board ว่างตามปกติ

## ทบทวนเมื่อไหร่
ถ้าทีมโตจนต้องมีคนนอกทีมเทคนิคเข้ามาดูสถานะงาน หรือถ้าต้องเชื่อมกับระบบรายงานผลของบริษัทที่ใช้ tracker กลาง
